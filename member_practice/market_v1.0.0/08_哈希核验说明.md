# 哈希核验使用说明

哈希可以理解为文件指纹。收到文件后重新计算，与负责人独立公告的原值一致，才能确认收到的是同一版。它发现文件差异，不能阻止修改，也不能单独证明代码由本人完成。

本次发放标识是 `QTP1-MARKET-FILES-1.0.0`，只对应当前同一文件夹里的单独文件。原完整包的 MANIFEST SHA 和核验命令不适用于这份平铺目录。

## 收到文件后的操作

1. 保存全部单独文件到同一个文件夹，保持原名，不通过 Excel 另存 CSV。只查看表格即可；股票代码按文本查看，保留前导零。
2. 从负责人另外发送的《00_发放公告.txt》取得“文件哈希清单 SHA-256”。这是信任起点，不能用自己改过的清单给自己证明。
3. 在该文件夹的 PowerShell 窗口中核对清单本身：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\09_文件哈希清单.txt'
```

把计算结果与公告中的 64 位摘要比较，大小写不影响十六进制值。然后运行标准库核验程序，下方占位文字必须替换为公告中的真实摘要：

```powershell
python '.\校验文件.py' --expected-manifest-sha256 负责人公告的64位摘要
```

工具需要 Python 3.10 或更高版本，不需要额外安装库。只有退出码为 0 且显示“通过”，才算通过。报告默认显示在窗口；若要保存到 work，可先创建 work，再重定向输出。

```powershell
New-Item -ItemType Directory -Force work
python '.\校验文件.py' --expected-manifest-sha256 负责人公告的64位摘要 > work/input_check.json
```

## 清单保护哪些文件

三张 CSV、两份原始 JSON、中文说明和核验程序都受保护。清单不对自身做哈希，公告在清单之外保存，避免循环引用。公告里也给出三个 CSV 的单文件摘要，便于单独检查。

所有个人代码、SQL、SQLite 和结果放在 work。新增个人文件可以正常使用，但不能更改清单列出的输入。缺文件、摘要不匹配时停止基线比较，保留核验输出，向负责人索取原文件。每次正式运行和提交前重跑一次；负责人使用自己保留的可信副本验收。

数据库由每人自行建立。不同 SQLite 文件页布局会使哈希不同，因此验收比较表内记录、类型、主键和数值，不把数据库文件哈希一致作为正确标准。源 CSV 的字节则必须与公告一致。
