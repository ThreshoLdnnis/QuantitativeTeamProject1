- 自行建立 `work/sql/Q01.sql` 至 `Q08.sql`，每个文件一条只读 SELECT；可用 WITH、子查询、JOIN、GROUP BY、HAVING。不要写建表、删改、PRAGMA、ATTACH 或多语句。提交查询文本，不能只交截图。

- 所有列名、列序、排序和空值按题面；使用 UTF-8、逗号分隔、不写索引，NULL/NaN 写为空字段。股票代码保持字符串。浮点验收 `rtol=1e-12, atol=1e-10`，不要提前四舍五入。
- 固定行情 CSV 的 turnover 没有原生 NULL。题目中的行情缺失由日历或股票池 LEFT JOIN 自然产生，不修改源数据来制造空值。

## Q04｜按日期和代码双键 JOIN

查询 `2020-02-03` 当天 `stock_universe.eligible=1` 且存在行情的股票。行情与股票池必须同时按 `date` 和 `symbol` 关联，按代码升序；状态字段保留原值。

结果列：`date, symbol, adj_close, can_buy, can_sell, status_known`。

## Q05｜从独立交易日历检查每日覆盖

对 `trading_calendar` 中 `2019-02-01` 至 `2019-04-30` 的每个日期输出一行，即使当天没有合格股票或行情也保留该日。依日期关联当天 `eligible=1` 的股票，再按日期和代码关联行情。按日期升序。

- `eligible_rows`：该日股票池中 `eligible=1` 的行数。
- `price_rows`：上述合格股票中实际存在行情的行数。
- `missing_price_rows`：合格股票中没有行情的行数。
- `adj_close_count`：上述已关联行情中，`adj_close` 非 NULL 的数量。

结果列：`date, eligible_rows, price_rows, missing_price_rows, adj_close_count`。

不能用 `COUNT(*)` 代替上述所有计数；理解 LEFT JOIN 保留行与 `COUNT(列)` 忽略 NULL 的区别。

## Q06｜合格但没有行情的明细

结果列：`date, symbol`。

## Q07｜区分未知状态与缺失行情

以全部 `stock_universe` 行为基准 LEFT JOIN 行情，包括 `eligible=0` 的行。按股票池 `eligible` 和行情 `status_known, can_buy, can_sell` 四列分组：缺失行情对应的三个状态字段保留 NULL，不能填成 0。

- `universe_rows`：该组股票池行数，包括没有行情的行。
- `price_rows`：该组实际匹配的行情行数。

按 `eligible, status_known, can_buy, can_sell` 依次升序；采用 SQLite 默认的 NULL 在前顺序。

结果列：`eligible, status_known, can_buy, can_sell, universe_rows, price_rows`。

结合结果解释：为何 `status_known=0` 且 `can_buy=1`，与行情缺失后 `can_buy IS NULL` 不能互换？解释写入个人说明，不添加到 SQL 结果。

## Q08｜三张表的主键审计

分别按预期键审计三张表：行情与股票池为 `(date,symbol)`，交易日历为 `date`。每张表输出一行，按 `table_name` 升序。即使没有重复，也输出完整统计；不要删除任何记录。

- `rows_count`：原始记录数。
- `key_count`：不重复键组数，双键须作为一对分组，不能分别数日期与代码。
- `duplicate_key_groups`：记录数大于 1 的键组数。
- `excess_rows`：每组除第一行以外的多余行总数，即各组 `n-1` 之和。

结果列：`table_name, rows_count, key_count, duplicate_key_groups, excess_rows`。

## Q09｜SQL 查询 → pandas 完整有序面板

自行编写 Python 查询函数。首先从 SQLite 独立查询 `trading_calendar` 中 `2019-01-01` 至 `2019-12-31` 的日期；代码集合取 `stock_universe` 全期所有不重复代码。建立“这些交易日 × 这些代码”的完整网格，分别按双键 LEFT JOIN 股票池和行情。将 SQL 查询结果交给 pandas，整理后导出 `Q09.csv`。

保留 `eligible=0` 的格子和没有行情的格子。状态、价格、成交量缺失时保留缺失值；`price_missing` 在找不到整条行情时为 1，找到时为 0。它不等同于“某个数值字段为空”。日期来自独立交易日历，不能从该股票已有行情取日期，也不能加入自然日周末。按日期、代码依次升序，每格一行。

结果列：`date, symbol, eligible, adj_close, volume, can_buy, can_sell, status_known, price_missing`。

## Q10｜SQL 查询 → pandas 日历对齐的 momentum20

使用 Q09 的完整 2019 年面板和从 SQL 单独读出的交易日历，在 pandas 中按代码、日期计算。每只股票先对齐独立交易日历；所有代码保留所有交易日，不做股票池筛选。

- 只有有限且严格大于 0 的 `adj_close` 算有效价格，其他值按缺失处理。
- `valid_price_count21` 为截至当日的最近 21 个交易日格子中，有效价格的数量，包含当日；不足 21 日时统计实际已有格子，因此输出整数 0～21。
- 只有最近 21 格全部有有效价格时，`momentum20 = 当日adj_close / 20个交易日前adj_close - 1`；其他位置为缺失值。只验证两个端点有效不够。
- 不前向填充、不填零、不删除缺口后再 `shift(20)`；不使用未来价格。起始不足 21 个交易日的格子也保留，收益留空。

导出 `Q10.csv`，按日期、代码依次升序，行集合须与 Q09 一致。

结果列：`date, symbol, valid_price_count21, momentum20`。

另在个人说明中选一个有缺口的代码，说明“已有记录向后移 20 行”和“独立交易日历向后移 20 日”的差别，并说明为何窗口内部缺失会使本题收益无效。若所用数据集没有缺口，使用另一数据集进行这部分解释。
