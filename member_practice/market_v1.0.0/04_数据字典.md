# 数据字典：先看懂三张表

适用分发版本：`QTP1-MARKET-FILES-1.0.0`。本版只单独发放真实教学数据，与原 `QTP1-DATA-1.0.0` 中 `market` 的三张表保持相同字节，没有重新下载或修改行情。

CSV 就是纯文本保存的表格。用 Excel 可以查看，用 Python 可以读取，再由每位成员自行导入 SQLite。开始时先认识下面三张表，不需要把所有说明文件都当作行情数据。

| 文件 | 内容 | 每行表示什么 | SQLite 表名 |
| --- | --- | --- | --- |
| `prices.csv` | 每日行情 | 一只股票在一个日期的价格、成交量和状态 | `stock_prices` |
| `calendar.csv` | 独立交易日历 | 一个研究交易日 | `trading_calendar` |
| `universe.csv` | 股票池成员资格 | 一只股票在一个日期的研究资格 | `stock_universe` |

## 1. 所有表共同遵守的约定

- 日期使用 `YYYY-MM-DD`，SQLite 保存为 `TEXT`。日期先后可以按这种规范文本排序；“下一交易日”要查日历，不能直接加一个自然日。
- 股票代码使用 `TEXT`，`000001` 的前导零是代码的一部分。使用 pandas 时显式指定 `dtype={"symbol": str}`；不要让 Excel 或程序先把它变成数字 `1`。
- `REAL` 表示小数，`INTEGER` 表示整数。状态列在 CSV 中可能写作 `True/False`，导入 SQLite 时按含义映射为 `1/0`。文本 `False` 不是“非空就为真”。
- 原始空数值应导入 SQL `NULL`。NULL 表示缺失，不是零、空字符串或字符串 `"NULL"`。当前 `prices.csv` 的 `turnover` 没有原生空值；LEFT JOIN 缺行情时仍会产生 NULL。
- CSV 只查看和读取，不另存覆盖。清洗、统计和新增字段放在自己的代码、派生表或输出文件中。
- 导入前检查重复键，遇到重复要报错并定位，不能静默丢弃一行来凑对行数。

## 2. 行情表 `prices.csv`

共 **50,927 行、13 列**。每个 `(date, symbol)` 组合唯一，例如“一只股票在某个交易日”只能有一条原始行情。SQLite 应建立组合主键或等价的唯一约束；日期必须属于独立日历。

| 列名 | SQLite 类型 | 含义与单位 |
| --- | --- | --- |
| `date` | TEXT | 行情日期，ISO 日期文本 |
| `symbol` | TEXT | 股票代码，保留前导零 |
| `open` | REAL | 未复权开盘价，元，正数 |
| `high` | REAL | 未复权最高价，元，正数；不低于开盘价和收盘价 |
| `low` | REAL | 未复权最低价，元，正数；不高于开盘价和收盘价 |
| `close` | REAL | 未复权收盘价，元，正数 |
| `adj_open` | REAL | 后复权开盘研究价格，正数；用于理论标签及模拟执行的价格代理 |
| `adj_close` | REAL | 后复权收盘研究价格，正数；用于日收益率、因子和收盘估值代理 |
| `volume` | REAL | 成交量，单位为股，非负；原始来源的“手”已乘 100，不要再乘一次 |
| `turnover` | REAL，可 NULL | 换手率，已转换为比例；`0.02` 表示 2%，不是 0.02% |
| `can_buy` | INTEGER | `1` 表示输入假设允许当日买入，`0` 表示不允许 |
| `can_sell` | INTEGER | `1` 表示输入假设允许当日卖出，`0` 表示不允许 |
| `status_known` | INTEGER | `1` 表示执行状态有可靠历史资料确认，`0` 表示未知 |

主键：`(date, symbol)`。原始表只有 `turnover` 允许空值，其他列应有有效值。成员需要自行实现建表、类型转换、约束和导入。

**为什么要区分 `close` 和 `adj_close`？** 公司分红、拆股等会改变价格的可比口径。连续收益研究使用本版提供的复权价格；未复权价格仍保留为原行情字段。后复权价格不是当天真实可下单的报价。本次回测用它和可分割持仓单位近似经济收益，不能把结果直接说成真实账户可实现收益。

**为什么有 `can_buy=1`，还要看 `status_known`？** 本版全部行情的 `status_known=0`。买卖标记由成交量等教学假设构造，不是已经核实的历史涨跌停、停牌或开盘盘口状态。若为复现基线许可未知状态参与模拟执行，必须显式记录 `allow_unknown_status=True` 或等价开关；输入仍保持未知，不能把这一假设改写为历史事实。

## 3. 股票池表 `universe.csv`

共 **50,970 行、3 列**。这是 1,699 个交易日与固定 30 个代码组成的完整网格，保留不合格记录。

| 列名 | SQLite 类型 | 含义 |
| --- | --- | --- |
| `date` | TEXT | 研究资格对应的交易日 |
| `symbol` | TEXT | 股票代码，保留前导零 |
| `eligible` | INTEGER | `1` 为本次研究中的合格成员，`0` 为不合格 |

主键：`(date, symbol)`。三列均不能为空；不能从原始表删除 `eligible=0`。研究中需要合格成员时，在查询或派生层显式筛选。成员资格缺失不能自动解释为合格，也不能凭未来成员名单形成过去信号。

`eligible` 是本教学数据的研究资格标记，不是对历史 ST、上市天数、退市及全部真实投资限制的完整验证。这是固定选取的 30 只股票，不能表述为整个 A 股市场或真实历史指数成分股。

## 4. 日历表 `calendar.csv`

共 **1,699 行、1 列**。

| 列名 | SQLite 类型 | 含义 |
| --- | --- | --- |
| `date` | TEXT | 冻结市场交易日，范围为 2019-01-02 至 2025-12-31 |

主键：`date`，不能为空，也不能重复。它决定滚动窗口、月末信号日和下一交易日。个股缺行情不代表全市场休市，所以不能用单只股票已有的行情日期替代独立日历，也不能自己补入周末和自然日。

## 5. 导入后必须核对的数字

| 检查项 | 固定值 |
| --- | ---: |
| 股票代码数量 | 30 |
| `stock_prices` 行数 | 50,927 |
| `stock_universe` 行数 | 50,970 |
| `trading_calendar` 行数 | 1,699 |
| 全网格无行情的格子 | 43 |
| `eligible=1` 但无行情的格子 | 37 |
| `eligible=0` 的股票池记录 | 6 |
| 原生 `turnover` NULL | 0 |
| 行情中 `status_known=0` 的记录 | 50,927 |

43 和 37 使用不同分母：前者检查全部“交易日 × 固定代码”，后者只检查合格成员。LEFT JOIN 后缺行情的价格、成交量和状态是 NULL；不能把它们填成零、False 或“已知停牌”。

2023–2025 正式评价段有 **727 个交易日、21,810 条行情，合格成员行情缺口为 0**。完整历史的缺口不能误写为正式段缺口。行情缺失、零成交量、不合格和状态未知也应分别处理。

## 6. SQLite 核对口径

三张输入表按上面的名称和字段建立，额外研究表可以另建。核对时按日期、代码比较实际内容：文本、整数和 NULL 精确一致；浮点比较允许 `rtol=1e-12, atol=1e-10` 的解析误差，不能人为四舍五入原值。

不同成员正确建立的 SQLite 文件可能具有不同的二进制哈希。数据库应比较表内内容、字段类型和唯一键；原始分发文件则按负责人另行公告的 SHA-256 核对。
